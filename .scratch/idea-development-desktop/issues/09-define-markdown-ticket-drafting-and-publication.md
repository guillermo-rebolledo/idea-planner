# Define Markdown ticket drafting and publication

Type: grilling
Status: open
Blocked by: 07

## Question

How should `/to-tickets` present its dependency-aware vertical-slice breakdown for discussion, capture approval of granularity and blocking edges, and publish one local Markdown document per approved Implementation Ticket without an external issue tracker?

## Comments

Agreed constraints:

- Preserve `/to-tickets`' native conversational quiz and display its ticket list and blocking edges before publication.
- Suggested approval fills the composer; user may revise or type custom feedback.
- The skill's existing approval becomes **Approve and create ticket files** and is the single final Planning Package acceptance.
- Mark Ready only after the complete `spec.md` and numbered ticket files validate.
- Partial publication remains in Ticket Review, preserves written drafts, identifies missing/invalid files, and retries by stable ticket identity without duplicates.
- No external tracker integration in the MVP.
